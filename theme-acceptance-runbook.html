维度必须覆盖不允许替代

固定种子数据

  • 商品：单规格、多变体、售罄、缺图、无评分各 1 个。
  • Collection：正常、空集合；Blog：正常、无封面。
  • Menu：3 级、空菜单、被删除引用。
  • 媒体：有效、404、慢加载；Newsletter：新邮箱、已订阅邮箱。
  • 文案：空值、1 字、超长、Emoji、中英文混排。
  • 链接：站内、站外、空值、非法 URL；颜色：HEX、Transparent、清空。

开始前资料

  • Build/commit/API/数据库版本与验收环境 URL。
  • 研发/测试已通过、未通过和已知问题。
  • 最终 UI 设计稿与本期不做项。
  • 真实 Storefront URL 和缓存刷新方式。
  • 已发布基线 + 独立验收草稿，禁止直接改生产店。

完整两天版

Day 1 · Editor 与 P0

13:30–15:00：Save、Discard、离开保护、Publish、缓存和异常恢复。

Day 2 · 其余组件、设置与前台

09:30–10:30：Video feed、Newsletter、Custom HTML。

10:30–12:00：P1 组件详细清单。

13:30–14:30：P2 组件与问题复测。

14:30–16:00：Theme settings 8 组与继承优先级。

16:00–17:00：真实 Storefront 三页面 × PC/M。

17:00–17:45：缺陷分级、证据和结论。

每个组件统一执行九步 添加 → 修改核心字段 → 触发条件字段 → 验布局边界 → 验失效资源 → 切 Mobile → Save 刷新 → 隐藏恢复 → Publish 后到真实前台核对。
这些不是测试细节，是验收前必须拍板的范围问题若不先定，测试通过与产品通过会使用不同口径。

缺陷严重级别

级别Theme 场景上线策略
Blocker数据丢失、草稿污染线上、发布覆盖错误主题、XSS、编辑器/前台核心配置完全不一致必须修复
P0Save/Discard/Publish 失败、Header/Footer 不全站、核心组件不可用、移动核心页溢出必须修复
P1单个布局/边界/资源回退错误，有绕行路径明确 owner 与日期后决策
P2轻微间距、非核心文案、低频视觉差异可带病上线并进入清单
